# M5 — Hardened upstream maintenance

**Status:** Planned (focused dependency remediation pulled forward in #82 / #83)

**Depends on:** M4

## Goal

Keep the fork maintainable as upstream evolves without allowing upstream feature
work, dependency updates, or release changes to silently weaken the security
contracts established by earlier milestones.

## Scope

- Define an explicit upstream intake/review procedure from pinned source commits or tags.
- Classify upstream changes by trust boundary: permissions, MCP surfaces, execution, browser observation, storage, secrets, network, packaging, or ordinary feature code.
- Require focused regression review when a change touches a security boundary.
- Keep dependency updates locked, auditable, and separated when they materially change native/runtime authority.
- Track intentionally diverged fork behavior so future rebases do not "restore" insecure upstream defaults by accident.
- Add automated guards for critical fork invariants that can be checked mechanically.

## Contracts

- Upstream provenance is evidence, not automatic approval.
- Security-sensitive merges remain reviewable as focused changes.
- Conflicts are resolved according to current fork contracts, not by choosing the newer side blindly.
- No milestone or Issue is closed because upstream changed; acceptance criteria must still be demonstrated in this fork.

## Out of scope

New product features unrelated to maintenance. They require their own roadmap milestone when approved.

## Pulled-forward dependency remediation — #82 / #83

Sharp is pinned from 0.35.3 to 0.35.4 with its upstream native packages/libvips,
and the compatible transitive Hono lock is refreshed from 4.13.2 to 4.13.7.
The lockfile was generated by npm with install scripts disabled, reviewed against
the previous package tree, and committed only after exact blob-hash verification.
No forced major upgrade, hand-written integrity value or audit suppression is used.
The temporary preparation workflow is absent from the final source tree.

Primary upstream review sources:
- https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c
- https://github.com/lovell/sharp/releases/tag/v0.35.4
- https://github.com/honojs/hono/security/advisories/GHSA-g6gw-c38x-mqfc
- https://github.com/honojs/hono/releases/tag/v4.13.7

`test/dependency-security-baseline.test.ts` exercises real synthetic PNG/AVIF
encoding, decoding/resizing, malformed-input rejection and decoded-pixel bounds.
This is native compatibility evidence, not an exploit reproduction or a claim
that an audit proves all dependencies secure. Exact-head CI, Security and Linux
candidate results are recorded in #82/#83. M1 remains the sequential milestone;
this patch does not complete M5 or authorize a merge/public release.
